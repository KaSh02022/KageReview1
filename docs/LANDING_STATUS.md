`HomePage.tsx` is composition plus the chapter-progress wiring. The rail
exposes indices 2–8 as chapters 01–07; the framing sections are not
destinations.

### How the motion works

`useChapterProgress` writes one number — `--chapter-progress` — to the stage
element once per animation frame. Each chapter subtracts its own index to get
a local value that is `0` when centred, negative before and positive after,
and every layer multiplies that by its own depth. There is no per-chapter
scroll listener and **nothing re-renders on scroll**. See D-057.

## Load-bearing details — do not "clean up"

These look incidental and are not. Each has a test that fails if it is removed.

- **`id="fandom-categories-section"` and `tabIndex={-1}`** on `CategoryExplorer`.
  The Fandom Core's "Skip intro" control focuses this element.
- **The heading "Explore fandoms"** — asserted by `App.test.tsx`.
- **`CinematicEntry` is untouched.** It owns the page's only `<h1>` and the
  WebGL → 2D → accessible-links fallback chain. `ChapterIntro` wraps it. Its
  stylesheet gained `--core-height` / `--core-min-height` overrides, with the
  previous values as defaults, so a host page can fit it into a composition.
- **Chapter CTAs are named for the franchise**, never "Explore {Category}" —
  the Fandom Core already owns a link by that name for all seven (D-061).
- **The chapter rail is buttons, not anchors.** A real `href="#chapter"` would
  rewrite `location.hash` and the router would read it as a route (D-032).
- **The hero entrance animates transform only, never opacity** (D-054).
  Fading the Core from zero puts its category labels below WCAG AA for the
  length of the animation.
- **No `will-change` on chapter layers.** Seven chapters made fourteen
  permanent composited layers, and Chromium silently stopped rasterising some
  of them — characters vanished mid-scroll on a phone with every automated
  check still green (D-062).
- **The intro reveals on mount, not on scroll.** `Reveal` takes `immediate`
  for anything in the opening screen; a negative `rootMargin` can otherwise
  leave already-visible content permanently unrevealed on a short fold.
- **The Core's height is driven by viewport height**, not width. A 1280×800
  desktop has less vertical room than a 768×1024 tablet.
- **No `#fragment` writes and no `window.location.search` reads** anywhere on
  this page. The app is on `createHashRouter`; either corrupts routing (D-032).

## Known, accepted

- **The masters are still in `public/assets/gemini/`** (85 MB) even though the
  runtime serves the renditions in `public/assets/gemini/web/` (2.1 MB). They
  are kept so `USE_MASTERS` stays a working switch, and because the asset
  freeze forbids deleting them. **Consequence: `dist/` carries ~85 MB of PNGs
  that no page requests.** Removing them from `public/` is a one-line change
  and does not touch the frozen staging copy in `_gemini_batch_01/` — but that
  is the Director's call, not an engineering one.
- **`character-books-alex-chen.png` is deliberately excluded.** There is no
  "books" category and no "Alex Chen" in the dataset.
- **Featured articles no longer appear on the landing.** The chapter
  architecture has no slot for a card grid; articles live on the hubs.
- **Six superseded section components remain on disk**, unreferenced:
  `LandingHero`, `CategoryExplorer`, `FeaturedCharacters`, `UniverseIntro`,
  `HowItWorks`, `FeaturedStories`. They tree-shake out of the bundle.
  Deleting them is the Director's call.
- **The Fandom Core chunk is 912 kB** (three.js), lazy-loaded and unchanged by
  this work.
